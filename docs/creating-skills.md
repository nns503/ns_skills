# 스킬 작성 안내

## 기본 형식

스킬마다 `skills/<skill-name>/SKILL.md`를 만듭니다. YAML 머리말의 `name`과 `description`은 필수입니다.

```yaml
---
name: meeting-notes
description: 회의 메모나 녹취 텍스트에서 결정 사항과 담당자별 할 일을 정리한다. 사용자가 회의록 작성이나 회의 후속 작업 정리를 요청할 때 사용한다.
---
```

위 내용은 형식 설명용 예시이며 등록된 스킬이 아닙니다. 폴더명과 `name`을 일치시키고, 템플릿 안내 문구를 실제 내용으로 바꿉니다.

## 한국어 작성 기준

- 한국어 제목, 설명, 절차와 요청 예시를 작성합니다.
- `description`에는 하는 일과 적용할 상황을 함께 적습니다.
- 결과물의 기본 언어는 한국어로 두되, 사용자가 지정한 언어가 있으면 따릅니다.
- 영문 용어는 정확한 식별이나 검색에 도움이 될 때 병기합니다.
- 경로, 명령어와 코드 식별자를 번역하지 않습니다.

## 지침에 담을 내용

일반적인 작업 설명보다 이 스킬에 필요한 판단 기준, 입력 정보, 결과물 형식과 완료 조건을 적습니다. 고정된 절차가 꼭 필요한 작업만 순서를 엄격하게 지정합니다.

특정 앱이나 도구에 의존하면 그 이름과 필요한 기능을 적습니다. Codex 전용 도구를 사용하는 스킬을 Claude에서도 동작한다고 표시하지 않습니다.

자료가 길어지면 `references/`로 나누고 언제 읽어야 하는지 `SKILL.md`에서 연결합니다. 실제 작업에 사용하는 코드만 `scripts/`에, 결과물에 쓰는 템플릿과 리소스만 `assets/`에 둡니다.

## 레퍼런스 활용

각 참고 문서는 관련 결정을 바꾸는 기준과 적용 조건을 중심으로 작성합니다. 링크를 많이 모으는 것보다 어떤 내용을 왜 채택했는지 기록하고, `SKILL.md`에서 필요한 시점에 읽도록 연결합니다. 관련 없는 참고 문서를 한 번에 모두 읽게 하지 않습니다.

외부 스킬은 코드·본문을 그대로 복사하기 전에 실제 내용과 판본·라이선스를 확인합니다. 원문을 포함하지 않고 독자적인 지침을 작성한 경우에도 설계 근거를 남깁니다. 실행 환경·서비스 버전이 달라질 수 있는 정보는 작업 시점의 공식 자료를 우선합니다.

TDD·자율성·확인 절차·테스트 수치 같은 운영 방침은 재사용 스킬에 전역 필수값으로 고정하지 않습니다. 프로젝트가 명시적으로 채택한 정책을 적용하고, 필요한 미정 항목을 해당 작업 전에 정리하도록 연결합니다. 스킬의 기본 제안과 프로젝트의 실제 결정을 구분합니다.

- [Agent Skills 공식 형식](https://agentskills.io/specification)
- [이번 워크플로의 레퍼런스 검토 기록](references.md)

## 추가 전 확인

1. 템플릿 안내 문구를 실제 내용으로 교체했는지 확인합니다.
2. 실제 사용자 요청으로 실행해 결과물을 확인합니다.
3. 유사하지만 이 스킬이 필요하지 않은 요청에도 설명이 적절한지 살펴봅니다.
4. 참고 자료와 스크립트 경로가 올바른지 확인합니다.
5. README에 한국어 설명, 요청 예시와 확인한 환경을 기록합니다.

실행 확인을 하지 않은 경우에는 확인한 환경을 비워 두거나 미확인으로 표시합니다.
