# 환경별 릴리스와 배포

요청된 대상을 확인하고 준비 → 실행 → 결과 확인으로 진행한다. 독립적인 릴리스 요청에서는 기존 구현·검증 결과부터 확인한다.

## 대상과 완료 범위

다음 항목을 구분한다. 프로젝트에서 이미 정한 값과 기존 사용자 권한은 재사용한다.

- **환경:** 개발, 스테이징, 운영 또는 프로젝트의 실제 환경명
- **플랫폼:** 웹·API 서버, 모바일 앱, 데스크톱 앱
- **배포 경로:** 미리보기, 내부 테스트, 베타, 정식 또는 프로젝트의 실제 경로
- **대상 버전:** 커밋·빌드·아티팩트 식별자와 적용할 설정
- **완료 목표:** 준비만, 패키징, 업로드, 심사 제출, 실제 출시, 배포 후 검증 중 요청된 범위

개발 환경 배포 권한을 운영 배포 권한으로 확대하지 않는다. 업로드 요청을 실제 공개 출시 요청으로 확대하지 않는다. 대상이 불명확해 외부 상태를 바꿀 수 없으면 가능한 준비를 완료하고 필요한 대상만 확인한다.

## 준비

필수 검증·CI 결과가 대상 버전에 해당하는지 확인한다. 워크플로 시작과 필수 작업의 성공을 구분한다. 필요한 환경 설정·비밀값의 연결, 계정·권한, 버전·서명·데이터 전환 조건을 점검한다. 해당 환경에 설정된 보호 규칙과 동시 배포 제어를 확인하고 존중한다. 기존 도구와 배포 스킬을 우선 활용하며, 없는 연결을 가정하지 않는다.

플랫폼에 맞는 자료만 읽는다.

- 웹·API 서버: [웹·서버 절차](references/web-server.md)
- 모바일 앱: [모바일 앱 절차](references/mobile-app.md)
- 데스크톱 앱: [데스크톱 앱 절차](references/desktop-app.md)

도구·서비스별 명령과 제약은 프로젝트 설정과 현재 공식 자료에서 확인한다. 변경 위험에 맞춰 이전 버전·데이터와 복구 가능성을 확인한다. 필수 검증 실패나 대상 불일치를 숨긴 채 실행하지 않는다.

## 실행과 확인

허용된 범위의 배포만 수행한다. 실행 후 상태·URL 또는 배포·패키지 식별자를 확인하고, 요청된 목표에 맞는 실제 동작을 검증한다. 실패하면 단계·영향을 파악하고 필요한 수정으로 돌아간다. 외부 차단 상태에서 무작정 재배포하지 않는다.

준비 완료, 패키징 완료, 업로드 완료, 심사 대기, 출시 완료와 동작 확인을 구분해 보고한다. 요청한 목표를 달성했으면 그 범위에서 마무리하되, 비동기 심사나 아직 수행하지 않은 출시·운영 검증은 남은 상태로 표시한다.

플랫폼·환경·경로, 버전, 수행 작업과 근거, 검증 결과, 남은 외부 절차와 복구 제약을 전달한다. 미래 확인이나 반복 감시는 별도 요청 없이 예약하지 않는다.
