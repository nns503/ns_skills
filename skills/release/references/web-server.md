# 웹·API 서버 배포

1. 대상 프로젝트·서비스·계정, 환경, 도메인과 배포 경로를 기존 설정에서 확인한다. 개발·미리보기·스테이징·운영 대상이 섞이지 않게 한다.
2. 대상 커밋과 빌드·아티팩트, 필수 CI 결과, 환경 변수·비밀값 연결과 외부 의존성을 확인한다. CI가 필요하지만 없으면 구현 작업으로 준비한다.
3. DB 변경이 있으면 기존 서버·새 서버와 데이터가 함께 동작하는 전환 순서를 확인한다. 파괴적 마이그레이션이나 복구 불가 조건을 단순 재배포로 해결할 수 있다고 가정하지 않는다.
4. 프로젝트의 배포 절차나 사용 가능한 배포 스킬로 요청 범위만 실행한다. 가능한 경우 검증한 동일 아티팩트를 환경에 맞는 설정으로 배포하고, 환경별 재빌드가 필요하면 그 결과를 다시 확인한다.
5. 배포 도구의 성공 응답과 실제 서비스 동작을 구분한다. 배포 식별자·URL, 상태 확인, 핵심 사용자 흐름이나 API 요청을 확인한다. 운영에 영향을 주는 테스트는 적절한 권한·데이터 범위에서 수행한다.
6. 실패하면 코드·설정·외부 서비스·데이터 전환 중 어느 문제인지 확인한다. 복구가 필요하고 허용된 경우 기존 절차를 따르며, DB까지 자동으로 되돌릴 수 있다고 가정하지 않는다.

GitHub Actions를 사용한다면 environment별 secrets·보호 규칙과 concurrency 설정을 확인한다. 같은 환경명을 쓴다는 이유만으로 다른 워크플로도 자동 직렬화된다고 가정하지 않는다. 배포를 시작한 실행과 실제 완료·검증 결과를 연결한다. 다른 CI/CD 공급자에서는 해당하는 설정을 확인한다.

배포 환경, 버전·식별자, 실제 동작 확인 결과, 실패·미검증 영역과 필요한 다음 조치를 전달한다.
