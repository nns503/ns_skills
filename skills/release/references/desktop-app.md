# 데스크톱 앱 패키징·배포

1. 운영체제·아키텍처, 연결할 서버 환경과 배포 경로를 확인한다. 직접 다운로드·내부 배포·스토어·자동 업데이트는 프로젝트에서 실제 사용하는 경로만 다룬다.
2. 현재 프로젝트 설정과 공식 도구 안내에서 버전·서명·필요한 배포 검증 조건을 확인한다. 민감한 서명 자료를 코드나 작업 기록에 포함하지 않는다.
3. 패키징 후 관련 대상에서 설치·실행·업데이트를 확인한다. 기존 사용자 데이터, 설정과 구버전 클라이언트·서버 호환성에 영향이 있으면 전환 동작을 검증한다.
4. 요청한 범위로 아티팩트를 배포하고, 배포 대상·버전·무결성을 확인할 근거를 남긴다. 자동 업데이트가 있으면 대상 채널과 제공 파일의 연결을 확인한다.
5. 업로드·공개·설치·업데이트·실행 확인 상태를 구분한다. 이미 설치된 앱과 데이터를 배포 취소만으로 되돌릴 수 있다고 가정하지 않는다.

미지원 운영체제·아키텍처와 실행하지 못한 검증을 명시한다. 실패 시 배포 경로·서명·패키징·설정·실행 문제를 구분하고 프로젝트의 복구·후속 업데이트 절차를 따른다.

## 플랫폼 확인

macOS 앱의 베타 배포에 TestFlight를 사용하는 경우에는 업로드·검토·테스터 배포 상태를 [Apple 공식 안내](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/)에서 확인한다. 직접 배포·다른 운영체제·자동 업데이트의 구체적인 서명·설치·갱신 절차는 실제 선택한 플랫폼과 배포 도구의 공식 자료를 추가로 확인한다. macOS 베타 배포 자료를 모든 데스크톱 배포의 근거로 일반화하지 않는다.
