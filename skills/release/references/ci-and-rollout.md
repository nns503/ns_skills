# CI 확인과 배포 후 판단

CI·배포 절차를 바꾸거나 운영 배포의 성공·복구 기준을 정할 때 읽는다. 기존 설정과 요청 범위 안에서 필요한 항목만 적용한다.

## CI와 대상 버전

필수 검사와 실행 조건을 프로젝트 설정에서 확인한다. 빠르게 확인할 수 있는 검사를 개발 중에 사용하고, 필요한 통합·대상 환경 검증을 적절한 시점에 배치한다. 모든 프로젝트에 같은 검사 종류·시간·커버리지 비율을 강제하지 않는다.

현재 커밋·설정·아티팩트와 결과가 일치하는지 확인한다. 워크플로가 시작됐거나 이전 커밋이 성공한 사실만으로 현재 변경의 성공을 판단하지 않는다. 실패를 통과시키기 위해 검사를 비활성화하거나 결과를 숨기지 않는다. 불안정한 검사는 원인과 실제 영향을 조사한다.

## 배포 계획

요청된 환경·버전과 핵심 동작의 성공 기준을 정한다. 실패를 알아볼 로그·상태·오류 신호와 가능한 복구 경로를 프로젝트 위험에 맞춰 확인한다. 기존 기능 플래그·단계 배포가 유용하면 재사용하고, 새 서비스를 모든 앱에 도입하지 않는다.

외부 사용자·클라이언트나 기존 데이터가 있으면 새·구버전의 공존과 전환 상태를 확인한다. 파괴적 삭제·타입 변경은 안전한 추가·전환 작업과 분리할 필요가 있는지 판단한다. 데이터 손실을 동반하는 변경에 되돌리기 명령이 있다는 이유만으로 복구 가능하다고 단정하지 않는다.

## 실행 후

대상 버전과 실제 상태, 핵심 사용자 흐름, 변경에 관련된 오류·성능 신호를 확인한다. 단순 상태 응답만으로 전체 기능 성공을 입증하지 않는다. 문제가 있으면 계속 진행·중단·기존 버전 복원·후속 수정 중 프로젝트 절차와 권한 범위에서 선택한다.

판단 기준은 실제 기준값·사용량·프로젝트 정책에 근거한다. 예제의 오류율·배포 비율·관찰 시간을 임의로 적용하지 않는다. 요청하지 않은 팀 통보·자동 병합·미래 감시를 실행하지 않는다.
