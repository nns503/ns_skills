# 사용자 흐름·시각 방향·실행 확인

새 UI를 설계하거나 사용자 흐름·상태가 바뀔 때 필요한 부분만 확인한다.

## 흐름과 상태

| 항목 | 결정할 내용 |
| --- | --- |
| 진입·이탈 | 어디에서 시작하고 뒤로 가기·취소·복귀가 어떻게 동작하는가 |
| 입력 | 필수·선택, 오류 위치, 입력 보존과 수정 방법 |
| 요청 중 | 진행 상태, 관련 동작의 재실행 가능 여부 |
| 결과 | 성공의 의미, 바뀐 데이터와 사용자가 다음에 할 일 |
| 실패 | 이해할 수 있는 안내와 재시도·복구 경로 |
| 권한·빈 상태 | 접근 불가와 데이터 없음의 구분, 가능한 다음 행동 |

모든 화면에 모든 상태를 추가하지 않는다. 실제 시나리오와 데이터 상태에서 생기는 분기만 다룬다.

## 시각 설계가 필요한 경우

신규 화면이나 시각 개편은 대상 사용자·실제 콘텐츠·정보 우선순위를 먼저 정한다. 기존 디자인 시스템이 있으면 재사용한다. 없으면 필요한 범위의 글자 위계·간격·색상 역할·배치 원칙을 짧게 정리한다.

예제의 색상·서체·애니메이션을 고정된 기본값으로 적용하지 않는다. 작은 기능 추가에 제품 전체의 시각 정체성을 바꾸지 않는다. 반복 카드·장식·움직임은 내용 전달이나 사용자 행동에 도움이 될 때 사용한다.

## 접근성과 실제 확인

포커스·키보드·라벨·읽기 순서를 관련 흐름에서 확인한다. 저장 성공·오류·진행 상태가 포커스를 옮기지 않고 나타나면 보조 기술에도 상태가 전달되는지 검토한다. 모든 알림을 강한 인터럽트로 만들지 않는다.

웹 UI를 검증할 때는 현재 렌더링된 화면과 접근 가능한 이름·역할을 확인한 뒤 조작 대상을 고른다. 완료 판단은 화면 캡처뿐 아니라 기대 상태·저장 결과·다음 동작으로 확인한다. 자동화 도구가 제공하는 조건 대기와 재시도 단언을 활용한다. 고정 시간 대기나 예제의 특정 로딩 조건을 모든 앱에 강제하지 않는다.

## 전문 지침 연결

웹 UI의 세부 검토에는 사용 가능한 Web Interface Guidelines 같은 웹 지침을, React·Next.js 또는 React Native·Expo가 실제 구성인 경우에는 해당 전문 지침을 선택할 수 있다. 이번 변경의 대상·버전·적용 규칙을 확인하고 관련 내용만 사용한다. 기술을 추정해 특정 라이브러리나 전체 규칙 묶음을 기본으로 설치하지 않는다.

여러 화면·작업이 같은 시각·상호작용 원칙을 사용해야 하면 공유 결정을 전달한다. 작은 기존 화면 수정에 전면 UX 설계나 새 문서 묶음을 요구하지 않는다.
