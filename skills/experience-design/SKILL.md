# 사용자 경험 설계

사용자 목표를 구현 가능한 흐름과 화면 상태로 연결한다. 기존 제품의 컴포넌트·내비게이션·디자인 규칙을 우선 확인한다. 새 UI·사용자 흐름·상태를 설계할 때 [경험 설계·실행 확인 기준](references/experience-checks.md)의 관련 부분을 읽는다.

## 설계

- 입력으로 요구사항·완료 조건, 기존 화면, 대상 기기와 실제 기술 제약을 받는다. 자료가 없으면 가정을 표시한다.
- 진입점 → 주요 행동 → 결과 → 다음 행동의 흐름을 정의한다. 경로·권한·데이터 상태에 따라 달라지는 부분을 표시한다.
- 관련 화면의 정상·빈 상태·로딩·오류·권한 부족·완료 후 동작을 필요한 범위에서 설계한다.
- 폼은 입력 기준, 오류 위치, 수정·재시도 동작을 정한다. 삭제 등 되돌리기 어려운 행동은 사용자가 결과를 이해할 수 있게 한다.
- 키보드·포커스·읽기 순서·라벨·상태 전달 등 변경에 관련된 접근성을 고려한다. 색상만으로 정보를 전달하지 않는다.
- 익숙한 기존 패턴과 플랫폼 기본 기능을 재사용한다. 시각 방향이 필요하면 실제 콘텐츠와 정보 우선순위를 근거로 정하고, 예제의 스타일을 고정 기본값으로 적용하지 않는다. 새 UI 라이브러리·디자인 체계는 실제 필요가 있을 때 검토한다.

현재 환경에 적절한 디자인·프로토타이핑 스킬이 있으면 연결한다. 이미지나 도구 결과가 없어도 설명 가능한 사용자 흐름과 상태를 전달할 수 있다. 실제로 만들지 않은 화면이나 실행하지 않은 사용성 검증을 만들었다고 보고하지 않는다.

## 전달과 완료

사용자 흐름, 화면·컴포넌트별 동작과 상태, 관련 접근성 기준, 검증할 시나리오와 기술 검토 항목을 전달한다. 독립적인 설계 요청이면 여기서 마무리한다.

핵심 시나리오를 구현할 수 있고 주요 오류·권한 분기가 정의되었는지 확인한다. 사용자 경험 변화가 없으면 오케스트레이션 기록에 근거를 남겨 생략할 수 있다.
