# 프로젝트 공통 규칙

프로젝트에서 실제로 사용하는 규칙과 도구 설정을 찾아 이번 작업에 적용한다. 조회 요청이면 확인·누락 정리까지만, 설정 요청이나 전체 개발 흐름이면 필요한 정책의 선택·기록까지 수행한다. 단독 요청으로 앱 구현을 시작하지 않는다.

## 조사

- 대상 경로에 적용되는 `AGENTS.md` 등 에이전트 지침, README·기여 안내, 기존 설계·명세를 확인한다.
- 변경할 코드 주변의 구조·이름과 포맷터·린터·타입·테스트 설정, 패키지 스크립트, CI를 확인한다.
- Git 작업을 할 때 브랜치·커밋·PR 템플릿과 최근 관례를 확인한다. 필요한 범위만 읽는다.
- 작업에 관련된 환경 설정, API 계약, 데이터 전환·지원 버전 정책을 확인한다.
- 기존 용어집·도메인 정의·기술 결정 기록을 확인한다. 사용자·기획·API·DB·코드의 용어가 다르거나 새 개념·중요한 결정을 정할 때 [도메인 용어와 결정 기록 기준](references/domain-language.md)을 읽는다.

사용자의 명시적 결정과 기존 프로젝트 규칙을 존중한다. 상충하는 규칙이 결과에 영향을 주면 근거와 선택지를 밝힌다. 지침 파일이 있다는 이유로 이미 받은 권한을 다시 묻지 않는다.

## 누락 판단과 프로젝트 설정

첫 조회에서는 기존 규칙·출처와 누락만 파악한다. 킥오프에서 목표·범위·위험이 정리되면 이번 작업에 필요한 미정 정책을 [프로젝트 설정 절차](references/project-setup.md)에 따라 분류·설정한다. 필요한 정보가 이미 있으면 킥오프를 반복하지 않는다.

이미 있는 정책은 재사용하고, 지금 필요한 핵심 선택은 해당 작업 전에 정한다. 작고 되돌리기 쉬운 선택은 명시한 기본값으로 진행할 수 있다. 아직 관련 없는 항목은 재확인할 시점을 남긴다. 문서가 없다는 이유로 모든 항목을 다시 질문하지 않는다.

TDD 범위·단계별 확인·테스트 비율·커버리지 목표는 프로젝트에서 선택할 정책이다. 사용자와 명시적으로 채택한 정책은 작업 범위에서 따르고, 외부 레퍼런스나 이 묶음의 기본 제안만으로 강제하지 않는다. 수치가 없으면 임의로 채우지 않는다.

[기본 제안](references/defaults.md)은 미채택 영역의 출발점으로 필요한 부분만 사용한다. 기본값을 합의한 정책이나 외부 실행 권한인 것처럼 표시하지 않는다. 중요한 충돌·공개 계약 변경은 기존 사용자 지시와 영향에 맞춰 해소한다.

커밋·PR 작업이나 해당 규칙을 정할 때는 [Git 협업 기준](references/git-workflow.md)을 읽는다. 스킬의 기본 제안과 외부 표준을 채택한 실제 프로젝트 정책을 구분한다.

포맷·린트·테스트 명령은 실제 설정에서 가져온다. 스택이 정해져야 선택할 항목은 기술 설계에서 채우고 관련 작업 전에 확인한다. 규칙 확인·설정 요청만으로 앱 코드·CI·도구 설정을 일괄 변경하지 않는다. 실제 설정 변경이 필요하면 구현 작업에 연결한다.

## 기록과 재검토

기존 정책 문서와 설정 파일을 우선 원본으로 사용한다. 새 기록이 필요하면 대상 앱의 `docs/project-rules.md`에 정책 값·적용 범위·상태·근거·재확인 시점을 남긴다. [프로젝트 규칙 양식](assets/project-rules.md)은 필요한 경우에만 복사한다. 기존 `AGENTS.md`의 관련 안내에 경로를 연결하되 기존 지침을 덮어쓰지 않는다.

합의한 정책과 작업별 위험 판단을 구분한다. 정책·범위·스택·배포 대상이 바뀔 때만 관련 항목을 재검토하고, 이미 받은 답·실행 권한을 다시 요구하지 않는다. 정책 변경의 이유와 영향을 남기고 관련 단계·검증 근거를 갱신한다. 검사를 통과시키기 위해 기준을 조용히 낮추지 않는다.

## 전달과 완료

다음 내용을 간결하게 정리하고 각 항목의 출처를 남긴다.

- 이번 작업에 적용할 정책 값·범위·상태와 출처
- 관련 검증 명령과 실행 조건
- 호환성·데이터·환경 관련 제약
- 관련 도메인 용어·현재 코드 이름의 매핑과 중요한 공유 결정
- 해당 작업 전에 해결할 미정 정책, 연기·해당 없음의 이유와 재확인 시점

필수인 미정 정책이 남으면 그 정책에 의존하는 작업으로 넘어가지 않고 독립적인 조사·설계를 진행한다. 기존 규칙 문서가 있으면 그 문서를 연결한다. 프로젝트별 정책을 전역 지침이나 스킬 설치본에 저장하지 않는다.
