# 실패 원인 조사와 수정

버그·테스트 실패·빌드 오류·예상 밖 동작이 발생하면 읽는다. 가설·수정·확인을 연결해 실패한 추측을 계속 덧붙이지 않는다.

## 재현과 실패 위치

- 기대 동작, 실제 결과, 입력·버전·환경·최근 변경을 확인한다. 로그·오류 메시지와 실행 결과를 읽는다.
- 가능한 범위에서 최소 재현을 만든다. 재현이 불안정하거나 외부 환경에서만 발생하면 확인한 사실과 필요한 관찰을 구분한다.
- 여러 구성요소를 지나면 경계별 입력·출력·설정 전달을 필요한 만큼 확인해 실패 위치를 좁힌다. 비밀값·개인 데이터를 진단 로그에 노출하지 않는다.
- 같은 코드베이스의 정상 사례와 비교하고, 잘못된 값이나 상태가 처음 생기는 지점을 추적한다.

## 가설과 최소 확인

가설을 `이 조건에서 이 원인이 이 결과를 만든다`로 구체화하고, 이를 확인하거나 반박할 작은 실험을 정한다. 가능하면 한 번에 하나의 원인을 검증한다. 근거가 반박되면 가설을 갱신하고 불필요한 실험 코드를 정리한다.

관련 없는 사용자 변경은 보존한다. 원인을 찾기 위해 운영 데이터를 수정하거나, 실패 출력을 없애려고 검증·오류 처리를 비활성화하지 않는다.

## 수정과 회귀 확인

원인에 맞는 변경을 하고 같은 재현 조건과 관련 호출자·기존 동작을 확인한다. 의미 있는 회귀 위험에는 수정 전 실패와 수정 후 성공을 구별하는 테스트 또는 재현 근거를 남긴다. 작은 수정에 테스트 프레임워크 전체를 새로 도입하지 않는다.

테스트가 계속 실패하면 원인·가정·실험 결과를 다시 검토한다. 고정된 시도 횟수만으로 아키텍처 전체를 바꾸거나 무조건 질문하지 않는다. 필요한 환경·정보·권한이 실제로 없으면 차단 조건과 독립적으로 진행할 수 있는 작업을 구분한다.

외부 쓰기 요청이 타임아웃 나면 성공·실패·결과 미확정을 구분하고, 실제 결과나 중복 실행 방지 계약을 확인한 뒤 재시도를 판단한다. 조사 중 결과가 미확정이면 수정 완료로 보고하지 않는다.

## 전달

재현 조건·실패 위치·원인 근거·수정·회귀 확인 결과·미확인 부분을 전달한다. 단순히 코드를 바꾼 사실을 버그 해결 근거로 대신하지 않는다.
